# 公开仓库脱敏规范

这个仓库是公开的。推上去的内容可能被缓存、抓取，删掉也收不回来。所以真实环境的信息不进 git：代码、测试、样例数据、文档、提交信息都算。

## 不能进仓库的

| 类别 | 例子 | 改成 |
|---|---|---|
| 真实公网地址 | 学校分配的公网段 | 文档专用段 `203.0.113.0/24` |
| 真实内网地址 | 管理网、学生机网段、实验室网段 | `192.0.2.0/24`、`198.51.100.0/24`（文档专用段），不够用时用 `10.99.0.0/16`、`192.168.99.0/24` |
| tailnet 地址 | `100.64.0.0/10` 段内任何地址 | 同上，按用途选一个文档段 <!-- public-safe-ignore --> |
| 真实 MAC | 抓包、交换机 MAC 表里的地址 | 本地管理地址 `02:00:00:xx:xx:xx`，或 `00:11:22:33:44:55` |
| 本机绝对路径 | `/Users/<名字>/...`、`/home/<名字>/...` | 相对仓库根目录的路径，或 `~/...` |
| 密码、令牌、密钥 | 交换机密码、API key、`.env` 内容 | 只从环境变量读；示例写 `CHANGE_ME` |
| 现场导出的原始数据 | 数据库 dump、迁移报告、巡检原文、真机截图 | 留在本机（`db-backups/`、`migration-reports/`、`test-results/` 都已 gitignore） |

## 替换规则

保留主机号、只换网段，这样替换后测试和文档仍然前后一致，熟悉现场的人也能对回去：例如真实管理网的 `.31` 换成 `192.0.2.31`。同一个真实网段在整个仓库里固定映射到同一个假网段。

测试样例要真实流量的形状时，先把采集到的原文按上面的规则替换，再放进 `fixtures/`。

## 自动检查

`backend/scripts/check-public-safe.mjs` 扫描所有被 git 跟踪的文件和还没 add 的新文件（被 .gitignore 忽略的除外），`npm run typecheck`（backend）会自动跑，也可以单独跑 `npm run check:public`。规则：

- 公网 IPv4：只允许三个文档专用段和 `8.8.8.8`、`8.8.4.4`、`1.1.1.1`、`1.0.0.1`
- `100.64.0.0/10`：一律不允许 <!-- public-safe-ignore -->
- MAC：只允许全 0、全 F、`00:11:22:33:44:55` 和本地管理地址（第一个字节的第 2 位为 1，如 `02:...`）
- `/Users/<名字>/`、`/home/<名字>/` 形式的绝对路径：不允许
- 真实内网前缀：写在仓库根目录的 `.public-safe.local`（已 gitignore，一行一个前缀，`#` 开头为注释）。这个文件只存在于各自的机器上，检查脚本读到就用，读不到就只做上面的通用检查。参与现场工作的人自己建一份

确实需要写一个会被误报的地址时（比如引用公开文档里的例子），在同一行加 `public-safe-ignore` 注释，并在评审时说明原因。

## 推送前

1. `cd backend && npm run typecheck`，看到 `[ok] public-safe` 再推
2. 本地分支历史里如果有过真实数据，不要直接推这条历史：在 `origin/main` 上用脱敏后的最终版本新建一个提交再推（历史里的旧提交同样会被公开）
3. 提交信息、PR 描述、issue 正文同样适用本规范
